# Agent Search 技术路线研究

## 1. 市场格局

### 1.1 主要玩家

| 产品 | 定位 | 索引方式 | 检索技术 | 输出 | 定价 |
|------|------|---------|---------|------|------|
| **Exa** (Metaphor) | 神经搜索 | 自有爬虫 | embedding + LLM rerank | 链接 + 摘要 | $0.01/1000 次 |
| **Tavily** | Agent 搜索 API | 自有爬虫 | 混合检索 + LLM | 答案 + 链接 | 免费 1000 次/月 |
| **Perplexity** | 答案引擎 | 自有索引 | 多引擎 + LLM 合成 | 答案 + 引用 | 订阅制 |
| **Brave Search API** | 独立索引 | 自有爬虫 | BM25 + 语义 | 链接 + 摘要 | 免费 2000 次/月 |
| **You.com** | AI 搜索 | 元搜索 + LLM | 多引擎 + LLM | 答案 + 链接 | API 付费 |
| **Kagi** | 高端搜索 | 元搜索 + 自有排序 | 多引擎 + 个性化 | 链接 + 摘要 | 订阅制 |
| **SearXNG** | 开源元搜索 | 无（纯聚合） | 引擎权重 + 位置 | 链接 | 自托管 |

### 1.2 关键趋势

1. **从链接到答案**：agent 不需要 10 个蓝色链接，需要直接可用的答案 + 引用
2. **从 BM25 到向量**：语义检索是标配，BM25 只做精确匹配补充
3. **从元搜索到自有索引**：元搜索是起步，终局是自有爬虫 + 索引
4. **从通用到垂直**：技术搜索（代码、文档、论文）是差异化方向

## 2. 技术路线对比

### 2.1 索引方式

| 方式 | 优点 | 缺点 | 代表 |
|------|------|------|------|
| **纯元搜索** | 零索引成本，覆盖广 | 受限于上游，延迟高，无新鲜度 | SearXNG |
| **元搜索 + 缓存** | 重复查询快 | 首次查询仍慢 | 我们 |
| **自有爬虫 + 索引** | 独立、新鲜、可控 | 基础设施重 | Exa, Tavily |
| **混合** | 元搜索补充自有索引 | 架构复杂 | Perplexity |

### 2.2 检索技术

| 技术 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **BM25** | 词频 + 逆文档频率 | 精确匹配强，快 | 无语义理解 |
| **向量检索** | embedding 相似度 | 语义匹配，跨语言 | 需要 GPU，近似匹配 |
| **混合检索** | BM25 + 向量 | 互补 | 架构复杂 |
| **LLM rerank** | cross-encoder 打分 | 精度最高 | 慢，需要 GPU |

### 2.3 排序架构

```
召回层          粗排层           精排层           输出
┌─────┐      ┌─────┐        ┌─────┐        ┌─────┐
│47 引擎│─────▶│BM25 │───────▶│CE   │───────▶│链接  │
│+ 本地 │      │top50│        │top10│        │+ 摘要│
└─────┘      └─────┘        └─────┘        └─────┘
                                    ↓
                              ┌─────┐
                              │LLM  │
                              │合成  │
                              └─────┘
```

## 3. 我们的位置

### 3.1 当前架构

```
用户查询
   │
   ├─ QueryCache (moka, TTL 5min)
   │
   ├─ LocalIndex (Tantivy)
   │   ├─ search_cached: 精确查询匹配
   │   └─ search_fulltext: BM25 over 爬取页面
   │
   ├─ aggregator::aggregate
   │   ├─ select_engines (general + 推断类别)
   │   ├─ fetch_raw_results (47 引擎并行)
   │   └─ score_results
   │       ├─ 粗排: BM25 + 位置权重 → top-50
   │       └─ 精排: jina-reranker-v2 (cross-encoder, INT8)
   │           └─ 混合: BM25 floor + CE relevance × authority × freshness
   │
   └─ crawl_result_pages (异步，top-10 结果爬取入索引)
```

### 3.2 指标

| 指标 | 值 | 来源 |
|------|-----|------|
| NDCG@10 | 0.860 | eval (73 查询) |
| MRR | 0.829 | eval |
| precision@10 | 0.586 | eval |
| 端到端延迟 | 26-39s | 实测 |
| 缓存命中延迟 | 0.38s | 实测 |
| 引擎覆盖 | 47 个 | engines.yaml |

### 3.3 优势

1. **精排质量高**：jina-reranker-v2 是 SOTA cross-encoder，NDCG 0.86
2. **覆盖广**：47 个引擎，技术搜索覆盖 StackExchange/GitHub/arXiv 等
3. **成本低**：INT8 量化，CPU 可跑，无 GPU 依赖
4. **自托管**：数据不出域，适合企业内部部署

### 3.4 差距

| 维度 | 我们 | 顶级水平 | 差距 |
|------|------|---------|------|
| **延迟** | 26-39s | <2s | 10-20x |
| **索引** | 无自有索引 | 自有爬虫 | 根本性 |
| **检索** | BM25 only | 混合检索 | 语义缺失 |
| **输出** | 链接列表 | 答案 + 引用 | agent 不能直接用 |
| **新鲜度** | 受限于上游 | 实时 | 中等 |
| **多语言** | 中英为主 | 多语言 | 中等 |

## 4. 技术路线

### Phase 1: 元搜索 + 精排（当前）

**目标**：70% 覆盖，验证技术路线

**已完成**：
- 47 引擎召回
- BM25 粗排 + cross-encoder 精排
- INT8 量化（4x 压缩，2-3x 加速）
- SBS 验证（vs rawweb/Bing）

**待解决**：
- 延迟 26s → 目标 <5s
- Brave 引擎限流（429）

### Phase 2: 混合检索

**目标**：语义理解，覆盖提升到 80%

**关键技术**：
- Embedding 模型：`bge-m3` 或 `jina-embeddings-v3`（多语言，8192 上下文）
- 向量索引：Tantivy 不支持向量，需要 `qdrant` 或 `lance`
- 混合排序：BM25 + 向量相似度 + CE 重排

**架构变化**：
```
查询
  ├─ BM25 → top-100 ─┐
  ├─ 向量检索 → top-100 ─┤
  └─ 合并去重 → top-50 ──▶ CE 精排 → top-10
```

**资源需求**：
- Embedding 模型（~200MB INT8）
- 向量数据库（qdrant ~100MB 内存）
- 额外 CPU/GPU 用于 embedding 计算

### Phase 3: 自有索引

**目标**：独立于上游，新鲜度可控

**关键技术**：
- 爬虫调度器（frontier、去重、优先级）
- 增量索引（Tantivy 已支持）
- 页面质量评分（PageRank 或类似）

**架构变化**：
```
爬虫集群
  ├─ 种子 URL（技术文档、博客、论坛）
  ├─ 调度器（优先级、频率、去重）
  ├─ 抓取 + 提取（已有 crawler.rs）
  └─ 入索引（Tantivy + 向量）

查询
  ├─ 自有索引（主）
  └─ 元搜索（补充）
```

**资源需求**：
- 爬虫基础设施（分布式、代理池）
- 存储（TB 级）
- 运维（监控、告警）

### Phase 4: 答案合成

**目标**：agent 直接可用，覆盖 90%+

**关键技术**：
- LLM 合成（Qwen3-4B 本地或 API）
- 答案 + 引用 + 结构化输出
- 多轮对话（追问、澄清）

**架构变化**：
```
top-5 结果
  ├─ LLM 合成答案
  ├─ 引用链接
  └─ 结构化输出（JSON）
```

**资源需求**：
- LLM（本地 4B 模型或 API 调用）
- Prompt 工程
- 评估体系（答案质量、引用准确性）

## 5. 延迟优化

### 5.1 当前瓶颈

| 阶段 | 耗时 | 占比 |
|------|------|------|
| 引擎召回 | 3.5s | 13% |
| Cross-encoder 精排 | 23s | 87% |
| **总计** | **26.5s** | **100%** |

### 5.2 优化方案

| 方案 | 预期延迟 | 代价 | 优先级 |
|------|---------|------|--------|
| **top-50 → top-20** | ~10s | 可能丢结果 | P0 |
| **换小模型** (bge-reranker-v2-m3) | ~5s | 精度略降 | P1 |
| **GPU/Metal 加速** | <1s | 需要硬件 | P1 |
| **v3 listwise** (10 文档一次) | ~3-5s | 只精排 top-10 | P2 |
| **max_length 512→256** | ~12s | 短文档够用 | P2 |
| **批量推理优化** | ~15s | 工程优化 | P3 |

### 5.3 推荐路径

**短期（1-2 周）**：
1. top-50 → top-30（减少 40% 计算量）
2. 评估 `bge-reranker-v2-m3`（278M 参数，比 jina-v2 快 3-5x）
3. 引擎超时从 30s 降到 10s（快速失败）

**中期（1-2 月）**：
1. 上 GPU（或 Apple Silicon Metal）
2. 引入 v3 listwise 模型
3. 批量推理优化

**长期**：
1. 自有索引（减少对上游依赖）
2. 答案合成（agent 直接可用）

## 7. 竞争分析

### 7.1 我们 vs Exa

| 维度 | 我们 | Exa |
|------|------|-----|
| 索引 | 元搜索 | 自有爬虫 |
| 检索 | BM25 + CE | embedding + LLM |
| 延迟 | 26s | <1s |
| 输出 | 链接 | 链接 + 摘要 |
| 成本 | 自托管 | $0.01/1000 次 |
| 优势 | 数据不出域 | 快、准 |

### 7.2 我们 vs SearXNG

| 维度 | 我们 | SearXNG |
|------|------|---------|
| 索引 | 元搜索 + 本地缓存 | 纯元搜索 |
| 检索 | BM25 + CE | 引擎权重 |
| 延迟 | 26s | 1-3s |
| 输出 | 链接 + 评分 | 链接 |
| 优势 | 精排质量高 | 快、轻 |

### 7.3 差异化定位

**我们的位置**：技术搜索（代码、文档、论文）的自托管解决方案

**目标用户**：
- 企业内部 agent（数据不出域）
- 开发者工具（IDE 插件、CLI）
- 垂直搜索（技术文档、论文）

**差异化**：
1. **数据主权**：自托管，不依赖第三方 API
2. **技术垂直**：47 个技术引擎，覆盖代码/文档/论文
3. **精排质量**：SOTA cross-encoder，NDCG 0.86
4. **成本**：CPU 可跑，INT8 量化

## 8. 结论

### 8.1 路线判断

**元搜索 + 精排是正确的起点，但不是终局。**

- ✅ 验证了技术路线（NDCG 0.86）
- ✅ 建立了精排能力（cross-encoder）
- ⚠️ 延迟是硬伤（26s vs <2s）
- ⚠️ 无自有索引是天花板

### 8.2 优先级

1. **P0：延迟优化**（26s → <5s）
   - top-50 → top-30
   - 评估小模型
   - 引擎超时优化

2. **P1：混合检索**（BM25 + 向量）
   - 引入 embedding 模型
   - 向量数据库
   - 混合排序

3. **P2：自有索引**（爬虫 + 索引）
   - 爬虫调度器
   - 增量索引
   - 页面质量评分

4. **P3：答案合成**（LLM）
   - 答案 + 引用
   - 结构化输出
   - 多轮对话

### 8.3 成功标准

| 阶段 | 延迟 | 覆盖率 | 输出 |
|------|------|--------|------|
| Phase 1 | <5s | 70% | 链接 |
| Phase 2 | <3s | 80% | 链接 + 摘要 |
| Phase 3 | <2s | 85% | 链接 + 摘要 |
| Phase 4 | <2s | 90% | 答案 + 引用 |
